# 司命（Siming）界面设计草案（UI）

> 版本：v0.6（开机自启显示真实状态）
> 日期：2026-11-23
> 依据：[PRD.md](PRD.md) v0.9
> 深度：定窗口、控件、状态与交互，不定像素级视觉
> 技术前提：.NET 10 + WinForms，原生控件优先

---

## 1. 范围与原则

### 1.1 范围

覆盖：托盘图标与菜单、主窗口、日志窗口、条目编辑对话框、退出确认对话框、启动失败/配置错误的提示。共 6 个界面单元。

### 1.2 原则

1. **托盘优先**：日常启停全部能在托盘菜单完成，不强制打开主窗口
2. **状态即时**：状态由进程事件驱动，点击后 ≤100ms 有反馈（圆点先变「启动中」）
3. **不打断**：后台启动失败不用模态框，用托盘气泡 + 行内红标 + 日志
4. **只读默认**：日志只读；配置以 `processes.json` 为准，界面只是编辑器
5. **原生控件**：不自绘窗口 chrome，保证高 DPI 与系统行为一致
6. **文案白话**：动作固定为「启动 / 停止 / 重启 / 查看日志」，名字古典，操作不古典

### 1.3 窗口地图

```
NotifyIcon（常驻）
├── 左键 ──────────────→ 主窗口（显示/聚焦）
├── 右键 ──────────────→ 托盘菜单
│                          ├── 条目子菜单（启动/停止/重启/查看日志，底部按配置追加快捷动作）
│                          ├── 全部启动 / 全部停止
│                          ├── 打开主窗口
│                          ├── 打开配置文件所在文件夹
│                          └── 退出
├── 主窗口
│     ├── 条目编辑对话框（模态）
│     ├── 删除确认（模态）
│     └── 日志窗口（非模态，每条目最多 1 个）
└── 退出确认对话框（模态，有运行中进程时）
```

**启动行为**：手动双击 exe → 显示主窗口；开机自启 → 只进托盘，不弹窗。

## 2. 托盘图标与菜单

### 2.1 图标

| 状态 | 图标 | 说明 |
|---|---|---|
| 空闲 | 「司」· 单色 | 黑白单色字，随任务栏明暗切换 |
| 有运行中 | 「司」· 绿 | 同一字形，绿色 `#2E9E44` |

- **字形不变，颜色即状态**：只用一个字，不换图形，托盘里最稳
- Tooltip：`司命 · 运行中 2/5`
- 不做多图标叠加数字（16px 下不可读）
- 两态只区分「有没有在跑」，不反映数量，也不区分单个条目的状态
- 绿色与主窗口「运行中」圆点同色，两处语义一致

**绘制方式**：

- `NotifyIcon.Icon` 只接受 `Icon`，需把字画到透明 `Bitmap`，再 `Icon.FromHandle(bmp.GetHicon())`，用完 `DestroyIcon` 防句柄泄漏
- 16×16 画布，字形约 13–14px 居中，字体 `Microsoft YaHei UI` Bold
- 单色态：黑字 + 1px 白描边；或白字 + 1px 黑描边（按任务栏明暗切换），保证浅色/深色任务栏都可见
- 运行态：绿字 + 1px 白描边；浅色任务栏下若对比不足，改用深一档的绿
- 主题检测读 `HKCU\...\Themes\Personalize\SystemUsesLightTheme`，监听 `WM_SETTINGCHANGE` 后重新生成
- 尺寸取 `SystemInformation.SmallIconSize`（等价于 `GetSystemMetrics(SM_CXSMICON)`），不要写死 16：100% 缩放是 16px，125% 是 20px，150% 是 24px，200% 是 32px；监听 `WM_DPICHANGED` 后重新生成
- 透明背景 + `TextRenderingHint.AntiAliasGridFit`

**风险**：「司」五笔，16px 下可能糊。真机看效果，必要时加重字重或把字号压到 12–13px 换取笔画间隙；实在不行再退回几何图形方案。

### 2.2 右键菜单

```
┌──────────────────────────────┐
│ ● Blog Dev            2h 13m │
│ ○ API Server          已停止 │
│ ◐ Worker              启动中 │
├──────────────────────────────┤
│ 全部启动                      │
│ 全部停止                      │
├──────────────────────────────┤
│ 打开主窗口                    │
│ 打开配置文件所在文件夹         │
│ ☑ 开机自启（已启用）          │
│ 退出                          │
└──────────────────────────────┘
```

- 菜单在 `Opening` 时动态重建，状态文字与可用项实时反映
- 「开机自启」的文字直接写出注册表里的真实状态：`已启用` / `未启用` / `被系统禁用` / `指向其他程序` / `读取失败`，勾选与否以真实状态为准，不看配置文件
- **已定**：条目行只负责展示与展开，不绑定任何直接动作；启停一律走子菜单，避免误触
- 点击条目行 → 展开子菜单：

```
Blog Dev  ● 运行中
├ 重启
├ 停止
├ ─────────
├ 查看日志
├ 打开工作目录
├ 复制命令
└ ☑ 随司命启动
```

- 子菜单项按状态启停用：已停止 → 只有「启动」「查看日志」「打开工作目录」「复制命令」；运行中 → 「停止」「重启」
- 「随司命启动」是勾选项，切换后立即写回 `processes.json`；保存失败会回滚并提示
- 「全部停止」在有运行中条目时才可用
- 条目配置了快捷动作时，底部再追加分隔线和动作项，见下

**v2：提取与快捷动作**（见 PRD §6.7）

```
● Blog Dev — 运行中 · 2h 13m
├─ 重启
├─ 停止
├─ ─────────────
├─ 查看日志
├─ 打开工作目录
├─ 复制命令
├─ ☑ 随司命启动
├─ ─────────────
├─ 打开链接
├─ 复制链接
└─ 复制密码
```

- 未配置 `actions` 时菜单到此为止，不留空分隔线
- 动作**平铺**，不套「其他」之类的子菜单：多一层悬停的代价高于菜单变长
- 位置固定在最后，前面加分隔线；子项顺序 = `actions` 数组顺序
- **结构由配置决定，可用性由运行时决定**：菜单里永远不增删项，只在做不了时置灰
- 置灰时机有两种，表现一致：模板引用的字段还没提取到（程序还没打印那一行）、条目已停止（启动时值已清空）
- 置灰项要留在菜单里，它就是「还在等程序输出」的唯一反馈；为了清爽去隐藏反而让人以为功能没了
- 置灰项的悬停提示要说明原因（「等待程序输出所需的值」），否则用户不知道在等什么
- **不展示值本身**：不显示地址、不显示密码明文；要拿值就点「复制链接」/「复制密码」
- 动作不进入进程状态机；执行失败只出气泡，不影响条目状态
- 动作多时子菜单会变长，建议 3–5 项；不做「超过 N 项自动收进子菜单」，避免同样配置在两次打开时层级不同

## 3. 主窗口

### 3.1 布局

```
┌──────────────────────────────────────────────────────────────────────────┐
│ [启动] [停止] [重启] [日志] │ [新增] [编辑] [删除] │ [↑] [↓] │ ☐ 开机自启 │
├──────────────────────────────────────────────────────────────────────────┤
│   名称          状态        运行时长  自动启动  命令           工作目录    │
│ ● Blog Dev      运行中      2h 13m    是        npm run dev    D:\projects\blog
│ ○ API Server    已停止 (1)  —                   dotnet run     D:\projects\api
│ ◐ Worker        启动中      0m 03s              node worker.js D:\projects\worker
│                                                                          │
│                                                                          │
├──────────────────────────────────────────────────────────────────────────┤
│ 运行中 1/3   ·   配置已加载          开机自启：已启用   processes.json     │
└──────────────────────────────────────────────────────────────────────────┘
```

- 控件：`ToolStrip` + `ListView(View.Details)` + `StatusStrip`
- 列：状态（圆点）、名称、状态文字、运行时长、自动启动、命令、工作目录
- 「自动启动」只显示 `是` 或空白，不写「否」：一列文字比一列对勾更省宽度
- 工具条的「开机自启」按钮：勾选态取自注册表实际状态；按钮不自己翻转，点击后按真实结果重新同步
- 状态圆点用 `ImageList` 的 4 张位图（按 DPI 生成），不自绘
- 列宽：名称/状态/运行时长/自动启动固定，命令与工作目录按比例分配，窗口可缩放
- **不支持点列头排序**：顺序 = 配置文件顺序，避免"看到的顺序"和"文件里的顺序"不一致
- 默认尺寸 960×520，最小 720×420

### 3.2 空态

```
              ┌──────────────────────────────┐
              │        还没有进程条目          │
              │   在 processes.json 里添加，   │
              │   或点下面的按钮开始。         │
              │        [ 新增条目 ]           │
              └──────────────────────────────┘
```

### 3.3 状态与按钮矩阵

| 条目状态 | 启动 | 停止 | 重启 | 日志 |
|---|---|---|---|---|
| 已停止 | ✓ | — | — | ✓ |
| 启动中 | — | ✓ | — | ✓ |
| 运行中 | — | ✓ | ✓ | ✓ |
| 停止中 | — | — | — | ✓ |

> 注：建议把 PRD FR-16 的「运行中才可停止」放宽为「启动中也可停止」，用于取消卡住的启动（等同强制结束）。停止中禁用重启，避免状态机打架。

### 3.4 交互

- 双击行 → 打开日志窗口
- 右键行 → 与工具条同项的上下文菜单
- 删除运行中条目 → 先确认「停止并删除？」，确认后停止再删除
- 关闭窗口 = 隐藏到托盘；首次关闭时气泡提示一次「司命仍在托盘运行」
- 选中变化即时刷新工具条可用态
- 状态列在退出码非 0 时显示 `已停止 (1)`，悬停显示退出时间

### 3.5 状态栏

- 左侧：`运行中 N/M`
- 中部：暂态消息，如「配置已重载 12:03:44」「启动失败：Blog Dev」
- 右侧：`开机自启：已启用` / `未启用` / `被系统禁用` / `指向其他程序` / `读取失败`
  - 正常状态用默认文字色，异常状态用错误色
  - 点击弹出详情：当前程序路径、注册表位置、值名与值；异常时可直接「重新登记」
  - 值以注册表为准，不以配置为准——配置说开着但启动项被系统禁用时，这里必须显示异常
- 最右：配置文件完整路径 + 「打开」链接

> 为什么状态栏要常驻这一项：开机自启是最容易「以为开了、其实没开」的开关。配置、注册表、任务管理器三处任何一处不一致，用户都看不出来，只能等下次登录才发现。状态栏常驻 + 托盘菜单文字 + 工具条按钮三处同源显示，才能一眼确认。

## 4. 日志窗口

```
┌─ Blog Dev — 日志 ────────────────────────────────────────────────┐
│ 运行中 · 已运行 2h 13m · npm run dev · D:\projects\blog           │
│ [暂停滚动] [复制全部] [清空] [重启] [停止]        ☑ 自动滚动       │
├──────────────────────────────────────────────────────────────────┤
│ > vite v5.4.0 dev server running at:                             │
│ > Local:   http://localhost:5173/                                │
│ > Network: http://192.168.1.10:5173/                             │
│ ...                                                              │
├──────────────────────────────────────────────────────────────────┤
│ 最近 200 行 · 累计 1,234 行 · 已丢弃 1,034 行                     │
└──────────────────────────────────────────────────────────────────┘
```

- 控件：只读多行 `TextBox`，`Font = Consolas`，垂直滚动条
- 非模态；每条目最多一个实例，重复打开则聚焦已有窗口
- 关闭日志窗口不停止进程
- **自动滚动**：默认开；用户向上滚动时自动暂停，出现「回到底部」浮层按钮
- **暂停滚动**只冻结视图，不停止接收（底部计数继续涨）
- 顶部信息行固定展示：状态、运行时长、命令、cwd
- 底部计数：`最近 200 行 · 累计 N 行 · 已丢弃 M 行`，让"日志被截断"这件事可见
- 高频刷新用 100ms 定时批量追加 + `WM_SETREDRAW` 包裹，避免逐行重排卡 UI
- ANSI 转义在写入前剥离；编码按条目配置解码（utf-8 / gbk）

## 5. 条目编辑对话框

```
┌─ 编辑条目 ────────────────────────────────────┐
│ 名称      [Blog Dev                        ]  │
│ 工作目录  [D:\projects\blog             ][…]  │
│ 命令      [npm run dev                     ]  │
│ Shell     [cmd ▾]          编码 [utf-8 ▾]     │
│ 环境变量  ┌──────────────┬─────────────────┐  │
│           │ PORT         │ 3000            │  │
│           │              │                 │  │
│           └──────────────┴─────────────────┘  │
│           [+ 添加] [− 删除选中]               │
│                                               │
│ ⚠ 工作目录不存在                              │
│                              [保存] [取消]     │
└───────────────────────────────────────────────┘
```

- 模态，约 520×440，`TableLayoutPanel` 布局
- 工作目录：只读文本框 + 「…」`FolderBrowserDialog`
- 命令：单行；不在 UI 里解析，整串交给 shell
- Shell：`pwsh` / `powershell` / `cmd` / `none`，新建条目按 pwsh → powershell → cmd 取第一个可用的
- 环境变量：两列 `DataGridView`（键/值），空行忽略
- 校验（保存时逐项）：
  - 名称非空且不与现有条目重名
  - cwd 存在
  - 命令非空
  - 环境变量键合法且不重复
- 错误就地显示在字段下方，`保存` 置灰直到合法
- 新增与编辑复用同一对话框，标题分别为「新增条目」「编辑条目」
- **不含「随司命启动」**：这是使用频率低、但改动即生效的开关，放在托盘条目子菜单里勾选；对话框保存时原值透传
- 保存时若条目缺少 `id` 自动生成并回写；`extract` / `actions` 与未知字段原样保留，界面不编辑（手写 JSON）

## 6. 退出确认对话框

```
┌─ 退出司命 ────────────────────────────────────┐
│ 还有 2 个进程在运行：                          │
│   ● Blog Dev                                  │
│   ● API Server                                │
│                                               │
│ 保留进程意味着它们继续运行，但司命不再管理它们。│
│                                               │
│ [结束所有并退出]  [保留进程并退出]  [取消]      │
└───────────────────────────────────────────────┘
```

- 默认按钮 = 「结束所有并退出」；`Esc` = 取消
- 「保留进程并退出」为次要按钮，文案必须带后果说明
- 无运行中进程时直接退出，不弹窗
- 三个按钮用自定义 `Form`，不用 `MessageBox`（需要自定义按钮文案）

## 7. 提示与异常

| 场景 | 呈现 | 行为 |
|---|---|---|
| 启动失败 | 行内红色 `!` + 托盘气泡 | 气泡点击 → 打开该条目日志；不弹模态 |
| 配置 JSON 解析失败 | 状态栏红字 + 一次性对话框 | 保留旧配置，提供「打开配置文件」「查看错误」 |
| 外部修改重载成功 | 状态栏暂态消息 | 3 秒后自动消失 |
| exe 目录不可写 | 启动时对话框 | 说明原因，提供「退出」「打开所在目录」 |
| 条目被删除但日志窗口开着 | 日志窗口保留 | 顶部改显示「条目已删除」，只读可复制 |
| 启动中被停止 | 状态转「停止中」→「已停止」 | 日志追加一行「已强制结束」 |
| 提取正则非法 | 状态栏红字提示一次 | 跳过该字段，其余字段与条目启动不受影响 |
| 快捷动作执行失败 | 托盘气泡 | 不弹模态、不改条目状态 |

**气泡使用约束**：只在"用户没看着这个条目"时发；主窗口在前台时只用状态栏，避免双份提示。

## 8. 状态颜色

| 状态 | 圆点色 | 说明 |
|---|---|---|
| 已停止 | `#8A8A8A` 灰 | 退出码非 0 时文字追加 `(code)` |
| 启动中 | `#D9A400` 琥珀 | 进程已创建，尚未确认稳定 |
| 运行中 | `#2E9E44` 绿 | 进程存活 |
| 停止中 | `#C26A00` 橙 | 已发中断，等待退出 |

- 颜色只做辅助，状态文字始终存在（色弱可用）
- 「启动中」由我们自己的状态机决定（创建成功即进入），不做就绪探测

## 9. 控件映射（WinForms）

| 界面单元 | 控件 | 备注 |
|---|---|---|
| 托盘 | `NotifyIcon` | 左键 `MouseClick`，右键 `ContextMenuStrip`；「司」字渲染为 `Icon` |
| 托盘菜单 | `ContextMenuStrip` | `Opening` 时重建，反映实时状态 |
| 主窗口列表 | `ListView` + `ImageList` | Details 视图；圆点位图按 DPI 生成 |
| 工具条 | `ToolStrip` | 文字按钮优先，v1 不引图标资源 |
| 状态栏 | `StatusStrip` | 三段：计数 / 消息 / 路径 |
| 日志 | `TextBox`（Multiline, ReadOnly） | 等宽字体；批量刷新 |
| 编辑对话框 | `Form` + `TableLayoutPanel` | 环境变量用 `DataGridView` |
| 退出对话框 | `Form` | 三个自定义按钮 |
| 气泡 | `NotifyIcon.ShowBalloonTip` | Win10/11 呈现为系统通知 |
| 高 DPI | `HighDpiMode.PerMonitorV2` | 布局用 Anchor/Dock，不写死像素 |

## 10. 关键流程

1. **日常启动**：托盘右键 → 条目 → 启动 → 圆点琥珀 → 绿；失败则红标 + 气泡 → 点气泡看日志
2. **改完代码重启**：托盘右键 → 条目 → 重启 → 橙（停止中）→ 琥珀 → 绿
3. **收工**：托盘 → 全部停止 → 逐个转灰；有失败的在状态栏汇总
4. **排错**：主窗口看到红标 → 双击开日志 → 暂停滚动 → 复制 → 改配置 → 重启
5. **改条目**：主窗口 → 编辑 → 保存 → 写回 `processes.json` → 文件监听回读（自写自读需防抖，避免二次重载）

| 键 | 动作 |
|---|---|
| `F5` | 启动 / 停止选中条目 |
| `Ctrl+R` | 重启选中条目 |
| `Ctrl+L` | 打开日志 |
| `Ctrl+N` | 新增条目 |
| `Enter` / `F2` | 编辑选中条目 |
| `Delete` | 删除选中条目 |
| `Ctrl+↑` / `Ctrl+↓` | 上移 / 下移条目 |
| `Esc` | 隐藏窗口到托盘 |
