# 司命（Siming）

Windows 托盘进程管理器：把常用命令收进托盘，一键启动、停止、重启，并把整棵进程树停干净。

适合管理 `npm run dev`、`python app.py`、`dotnet run` 这类需要长期运行、又不想一直开着终端的命令。

## 关于「司命」

「司」是掌管，「命」是生命、命运。「司命」在中文里指掌管生命的神明：《楚辞·九歌》里有《大司命》《少司命》，民间也把灶神称作「东厨司命」。

用它来命名进程管理器，是一个小小的比喻：每个进程都有自己的「命」——启动是生，停止是死。司命负责决定它们何时开始、何时结束；结束时要连子进程一起收干净，不留残余。

托盘图标取「司」字：空闲时是单色，有进程运行时变绿。

## 能做什么

- 为每个项目配置一条「工作目录 + 命令」
- 从托盘或主窗口启动、停止、重启
- 停止时先尝试正常中断，5 秒未退出就强制结束整棵进程树
- 进程自己退出后只标记为「已停止」，不会自动重启
- 查看每个条目的实时日志（默认最近 200 行）
- 条目可标「随司命启动」，司命启动时自动拉起
- 从程序输出里提取地址、密码等字段，做成托盘菜单里的快捷动作
- 开机自动启动，登录后静默进托盘
- 单实例运行，重复启动会唤起已有窗口
- 自动适配高 DPI（4K 200% 等）
- 同一份 exe 可作为 MCP 服务，让 AI 帮你管理条目

## 目录里有什么

```text
D:\tools\Siming\
├── Siming.exe        主程序（同时提供 --mcp 模式）
├── processes.json    配置：条目、日志行数、开机自启
└── mcp.token         本机控制接口令牌（使用 AI 接入时才会用到）
```

整个目录可以直接拷贝到其他位置或其他电脑，配置会跟着走（目标电脑需要满足[系统要求](#系统要求)）。

## 快速开始

1. 把 `Siming.exe` 放到一个**有写权限**的目录，例如 `D:\tools\Siming`。
2. 双击运行。首次启动会在 exe 同目录创建 `processes.json` 和 `mcp.token`。
3. 托盘出现「司」图标，同时打开主窗口。
   - Windows 11 如果没看到图标，点任务栏右下角的 `^` 展开隐藏图标。
4. 点「新增」，填写：
   - **名称**：例如 `Blog Dev`
   - **工作目录**：例如 `D:\projects\blog`
   - **命令**：例如 `npm run dev`
   - **Shell**：新建时默认按 `pwsh` → `powershell` → `cmd` 取本机可用的第一个；也可手动选 `none`（直接执行 exe）
5. 保存后选中条目，点「启动」。状态变为「运行中」，托盘图标变绿。
6. 想让它在司命下次启动时自动拉起：托盘右键该条目 → 勾选「随司命启动」。
7. 关闭主窗口只是隐藏到托盘，不会退出；要退出请用托盘右键菜单 →「退出」。

> 约 4 MB 的版本需要安装 .NET 10 Desktop Runtime；约 51 MB 的自包含版本不需要。详见[系统要求](#系统要求)。

## 主窗口

列表显示：

| 列 | 说明 |
|---|---|
| 名称 | 条目名称 |
| 状态 | 已停止 / 启动中 / 运行中 / 停止中 |
| 运行时长 | 本次运行了多久 |
| 自动启动 | 勾选「随司命启动」的条目显示 `是`，否则留空 |
| 命令 | 实际执行的命令 |
| 工作目录 | 命令运行的目录 |

工具条：启动、停止、重启、日志、新增、编辑、删除、上移/下移、重载配置、打开配置、开机自启。

双击条目可以直接打开日志。

### 快捷键

| 快捷键 | 作用 |
|---|---|
| `F5` | 启动 / 停止选中条目 |
| `Ctrl+R` | 重启选中条目 |
| `Ctrl+L` | 查看日志 |
| `Ctrl+N` | 新增条目 |
| `Enter` / `F2` | 编辑条目 |
| `Delete` | 删除条目 |
| `Ctrl+↑` / `Ctrl+↓` | 上移 / 下移 |
| `Esc` | 隐藏主窗口 |

## 托盘菜单

- **左键**托盘图标：打开主窗口
- **右键**托盘图标：打开菜单

每个条目都有一个子菜单，根据当前状态提供：

- 启动 / 停止 / 重启 / 取消启动
- 查看日志
- 打开工作目录
- 复制命令
- 随司命启动（勾选后，司命下次启动时自动拉起该条目）

配置了 `extract` / `actions` 的条目，底部还会多出几个快捷动作，见[提取与快捷动作](#提取与快捷动作)。动作在值还没提取到时是灰的，悬停会说明原因（「等待程序输出所需的值」或「尚未支持」）。

菜单底部还有：全部启动、全部停止、打开主窗口、打开配置文件所在文件夹、开机自启、退出。

## 日志

- 只读窗口，默认保留最近 **200 行**，可在 `processes.json` 的 `logLines` 中调整（100–5000）
- 向上滚动时自动暂停；点「回到底部」恢复跟随
- 工具条可以重启/停止条目、复制全部、清空、切换自动滚动
- 日志只存在内存里，**退出司命后清空**

## 退出

托盘右键 →「退出」时有三个选择：

| 选项 | 行为 |
|---|---|
| 结束所有并退出 | 停止所有运行中的条目，然后退出 |
| 保留进程并退出 | 司命退出，进程继续运行，但不再受司命管理 |
| 取消 | 不退出 |

如果司命异常退出，会尽量结束自己启动的进程，避免端口被占用。

## 开机自启

这里有两层，别混淆：

**1. 司命自己开机启动（全局）**

在主窗口工具条或托盘菜单里勾选「开机自启」。司命会在当前用户的启动项中登记，不需要管理员权限；登录后以 `--tray` 静默启动，不弹主窗口。移动程序目录后启动一次司命会自动校正启动项；如果没有，重新勾选一次即可。

**2. 条目随司命启动（每个条目）**

托盘右键 → 条目 → 勾选「随司命启动」，主窗口的「自动启动」列会显示 `是`。它只在**司命启动时**生效，不管司命是被你手动打开还是开机自启拉起来的；勾选后立即写回 `processes.json`，不需要打开编辑对话框。

两个都勾上，效果才是「登录后自动跑起来」。

## 配置

配置文件固定为 **exe 同目录**的 `processes.json`，不写 `%APPDATA%`。参考 [processes.sample.json](processes.sample.json)：

```json
{
  "version": 1,
  "settings": {
    "logLines": 200,
    "startWithWindows": false
  },
  "entries": [
    {
      "id": "blog-dev",
      "name": "Blog Dev",
      "cwd": "D:\\projects\\blog",
      "command": "npm run dev",
      "shell": "cmd",
      "encoding": "utf-8",
      "env": { "PORT": "3000" },
      "autoStart": false
    }
  ]
}
```

> JSON 中的 Windows 路径需要把反斜杠写成 `\\`，例如 `D:\\projects\\blog`。
>
> 上面是最小示例；带提取与快捷动作的完整写法见 [processes.sample.json](processes.sample.json)，或直接看下一节。

### 字段说明

| 字段 | 说明 |
|---|---|
| `name` | 条目名称，建议唯一 |
| `cwd` | 工作目录，必须是已存在的绝对路径 |
| `command` | 要执行的命令，会交给 `shell` 执行 |
| `shell` | `pwsh` / `powershell` / `cmd` / `none`（直接执行 exe）；新建条目的默认值按 pwsh → powershell → cmd 取第一个可用的 |
| `encoding` | 输出编码：`utf-8`（默认）/ `gbk` |
| `env` | 追加或覆盖环境变量；值为 `null` 表示删除该变量 |
| `autoStart` | 司命启动后自动拉起该条目 |
| `id` | 稳定标识，界面会自动生成，一般不用改 |
| `extract` | 从条目输出里提取字段，见「提取与快捷动作」 |
| `actions` | 条目子菜单底部的快捷动作，见「提取与快捷动作」 |

`settings`：

| 字段 | 说明 |
|---|---|
| `logLines` | 每个条目保留的日志行数，默认 200，范围 100–5000 |
| `startWithWindows` | 是否开机自启 |

可以在界面里编辑，也可以直接改 JSON。保存后会自动重载；如果运行中改坏了 JSON，司命会继续使用当前配置，并在状态栏提示错误。启动时文件有误会给出提示，并以空配置启动。

> 修改正在运行的条目后，界面会询问是否立即重启使新配置生效。

### 命令示例

| 场景 | `shell` | `command` |
|---|---|---|
| Node / npm | `cmd` | `npm run dev` |
| Python | `cmd` | `python app.py` |
| .NET | `cmd` | `dotnet run` |
| Windows PowerShell 脚本 | `powershell` | `& 'D:\scripts\run_server.ps1'` |
| PowerShell 7 脚本 | `pwsh` | `& 'D:\scripts\run_server.ps1'` |
| 直接运行 exe | `none` | `D:\tools\server\server.exe` |

命令会整体交给对应的 shell 执行；路径里有空格时，记得用引号包起来。

不写 `shell` 或从界面新建条目时，按 `pwsh` → `powershell` → `cmd` 取本机第一个可用的。上表的 `cmd` 是最稳妥的写法：`npm`、`python`、`dotnet` 在三个 shell 下都能跑，但 PowerShell 对 `&`、`&&`、引号的处理和 cmd 不同，跨机器分享配置时用 `cmd` 更保险。

## 提取与快捷动作

有些程序启动后会把地址、密码这类信息打印在输出里。给条目加 `extract`，司命就从日志里把值取出来；再加 `actions`，条目子菜单底部会多出几个快捷动作，可以一键打开或复制。

```json
{
  "id": "opencode",
  "name": "OpenCode",
  "cwd": "D:\\projects\\app",
  "command": "opencode serve",
  "extract": {
    "url": "server listening on (https?://\\S+)",
    "password": { "regex": "server password (\\S+)", "secret": true }
  },
  "actions": [
    { "label": "打开链接", "type": "open", "target": "${url}" },
    { "label": "复制链接", "type": "copy", "text": "${url}" },
    { "label": "复制密码", "type": "copy", "text": "${password}" }
  ]
}
```

菜单里会变成：

```
● OpenCode — 运行中 · 2m 13s
├─ 重启
├─ 停止
├─ ─────────────
├─ 查看日志
├─ 打开工作目录
├─ 复制命令
├─ ─────────────
├─ 打开链接
├─ 复制链接
└─ 复制密码
```

### 提取（`extract`）

| 写法 | 说明 |
|---|---|
| `"url": "正则"` | 简写。取第 1 个捕获组；没有捕获组时取整个匹配 |
| `{ "regex": "..." }` | 完整写法 |
| `"secret": true` | 值只给动作用，不进 MCP、不进诊断信息 |
| `"mode": "first"` | 默认。取到一次就固定，直到条目重启 |
| `"mode": "latest"` | 每次都更新，适合会变的地址（如 `dotnet watch` 热重载后的端口） |

- 只匹配单行：一条日志就是一次匹配，不跨行
- 只从该条目自己的输出（stdout 与 stderr）里取
- 取到的值只存在内存里，条目停止即清空；程序还没打印出那一行时，对应菜单项是灰的，这是正常的
- 正则写错不会影响启动，只在状态栏提示，并跳过该字段
- `secret` 只约束**提取结果**的流向；程序自己打印的那行原文仍然在日志里，日志窗口照常能看到

### 动作（`actions`）

| `type` | 行为 |
|---|---|
| `open` | 用默认程序打开 URL 或路径 |
| `copy` | 复制到剪贴板 |
| `command` | 预留，当前版本不执行，菜单里显示为灰色 |

- 模板里可以写 `${url}` 这样的提取变量，也可以写内置的 `${cwd}` `${pid}` `${name}` `${id}` `${state}`
- 拼接写在动作里，不在提取里：`"target": "http://${host}:${port}"`
- 任一变量取不到值，整项置灰，不会部分替换
- 动作平铺在条目子菜单底部，不套一层子菜单；建议控制在 3–5 项，否则子菜单会变长
- 快捷动作与提取值都不通过 MCP 暴露：AI 客户端看不到、也触发不了

## 用 AI 管理（MCP）

同一份 `Siming.exe` 也可以作为 MCP 服务运行，不需要额外程序。以 Claude Desktop 为例：

```json
{
  "mcpServers": {
    "siming": {
      "command": "D:\\tools\\Siming\\Siming.exe",
      "args": ["--mcp"]
    }
  }
}
```

Cursor、VS Code、OpenCode 等客户端的配置见 [docs/mcp.md](docs/mcp.md)。

配置后可以直接对 AI 说：

- 「把 `D:\projects\blog` 的 `npm run dev` 加进司命，名字叫 Blog Dev」
- 「启动 Blog Dev，然后给我最近 50 行日志」
- 「把 Blog Dev 的端口改成 8081，然后重启」

说明：

- 司命主程序没运行时，配置类操作会直接改 `processes.json`；启动/停止类操作会自动拉起托盘程序。
- 日志只在主程序运行期间存在，主程序没运行时读不到。
- 修改运行中的条目不会自动重启；需要再让 AI 重启，或在界面里确认重启。
- 控制接口只绑定本机 `127.0.0.1:17321`，使用 `mcp.token` 鉴权。不要把令牌发给别人。

## 系统要求

- Windows 10 / 11，x64
- 普通使用不需要管理员权限；命令本身需要管理员权限时，请以管理员身份运行司命

两种发布版本，功能完全一样，按需选择：

| 版本 | 大小 | 需要安装 .NET | 内存特点 |
|---|---|---|---|
| 框架依赖版（默认） | 约 4 MB | 需要 .NET 10 Desktop Runtime | 较低，每个进程约 10–20 MB |
| 自包含版 | 约 51 MB | 不需要 | 较高，每个进程约 50–70 MB |

### 便携使用

- 配置和程序放在同一目录，不写 `%APPDATA%`
- 拷贝整个目录即可迁移
- 分享程序目录时，不要带上 `mcp.token` 和 `processes.json`；首次启动会自动生成新令牌，配置按需重新添加
- `mcp.token` 是本机控制接口的密钥，不要随目录公开分享

## 常见问题

| 现象 | 处理 |
|---|---|
| 托盘里找不到图标 | Windows 11 点 `^` 展开隐藏图标；或在任务栏设置里允许显示 |
| 任务栏图标空白或还是旧图标 | 升级后重新固定一次；Windows 会缓存任务栏图标 |
| 启动失败 | 检查工作目录是否存在、命令是否能手动执行、Shell 是否选对；打开日志看错误 |
| 停止后还有残留进程 | 司命会先正常中断，5 秒后强制结束整棵进程树；如果之前选过「保留进程」，该进程已不再受管理 |
| 改了配置没生效 | 检查 JSON 是否合法；状态栏会显示配置错误；修正后自动重载 |
| AI 看不到 `siming_*` 工具 | 确认客户端配置里带了 `"args": ["--mcp"]`，然后重启客户端；详见 [docs/mcp.md](docs/mcp.md) |
| 日志为空 | 日志只在内存中；确认主程序正在运行、条目已经产生输出 |
| 控制接口报端口占用 | 17321 被其他程序占用；关闭冲突程序后重启司命 |
| 内存占用偏高 | 确认使用的是约 4 MB 的框架依赖版；51 MB 自包含压缩版每个进程会多占几十 MB |
| 快捷动作一直是灰的 | 正则还没命中。打开日志确认那一行是否真的打印了；条目已停止时，提取值会被清空并置灰，这是预期行为 |
| 程序启动几秒后自己退出了 | 看日志最后一行有没有 `(Y/N)` 之类的提问——stdin 是空设备，没人回答它。换用该程序的无交互参数，或用环境变量关掉（例如 OpenCode 的 `OPENCODE_DISABLE_AUTOUPDATE=1`） |
| 提取到的地址是旧端口 | 字段用了默认的 `mode: first`，取到一次就冻结；端口会变的程序（如 `dotnet watch`）改成 `"mode": "latest"` |

## 已知限制

- 仅支持 Windows
- 不提供自动重启、健康检查、端口检测、文件监听或构建流水线（有意保持简单）
- 日志只在内存中，每个条目最多 5000 行，退出后丢失
- 子进程的 stdin 接的是空设备：程序如果启动时弹交互式提问（`(Y/N)` 之类），司命没法回答，程序可能直接退出。请用该程序自带的无交互参数或环境变量关掉提示
- `actions` 的 `command` 类型尚未实现，菜单里显示为灰色
- 提取只做单行正则，不支持跨行拼接；需要组合值时在动作模板里拼（`http://${host}:${port}`）
- 选择「保留进程并退出」后，子进程的输出管道会关闭；个别程序可能因此自行退出
- 托盘图标的明暗主题只在启动时读取，切换系统主题后需要重启司命
- MCP 仅支持本机 stdio，不支持远程连接
